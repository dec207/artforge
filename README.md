# artforge

studio_d의 에셋 작업장. ComfyUI로 만들고, 모아 보고, 골라 공개한다.

낱장 생성은 `comfy-mcp`가 맡는다(전역 스코프라 어디서든 대화로 부른다).
동작 프레임은 `rig`가 만들고, `forge`가 결과를 축적하고 검색한다.

## 쓰기

```sh
./forge                 유입 → 만료 정리 → 브라우저 (127.0.0.1:8420)
./forge flag <id>…      공개 플래그. 만료가 면제된다
./forge replay <id>     저장된 레시피로 다시 만든다 (--seed 로 시드 교체)
./forge publish         플래그된 것만으로 public/ 을 만든다
```

`uv`가 의존성을 알아서 잡는다. 설치할 것도 활성화할 것도 없다.

## 규율을 요구하지 않는다

옛 구성은 "PNG와 json을 짝으로 커밋한다"는 규칙을 요구했고, 지켜지지 않아 쓰이지
않았다. 지금은 아무것도 옮기지 않아도 된다.

**모든 PNG가 자기를 만든 그래프를 tEXt 청크에 품고 있다.** 확산 그래프에서는
체크포인트·LoRA·프롬프트·시드가, 리깅 그래프에서는 파츠·회전각·배율이 나온다.
`./forge`를 열면 원천을 훑어 새것만 들인다. 위치는 `comfy which`로 물어본다.

## 움직임은 샘플러가 아니라 노드가 만든다

걷기 6프레임을 확산 모델로 매번 새로 뽑으면 프롬프트에 없는 세부 — 머리띠·양말
높이·신발 높이 — 를 프레임마다 새로 발명한다. 하나를 고치면 다른 것이 깨진다.

`rig`는 확산 모델을 기준 포즈 한 장에만 쓴다. 그 뒤로 샘플러가 없다. 같은 픽셀을
회전·배치할 뿐이라 액세서리가 달라질 방법이 **구조적으로** 없다.

```sh
./rig cut  walk-girl              기준 포즈를 머리·상체·양다리로 자른다 (1회)
./rig play walk-girl walk         동작 프레임을 합성한다
./rig play walk-girl walk --heads 7   같은 파츠로 7등신
```

파츠(`casts/<이름>/parts.json`)와 각도표(`motions/<동작>.json`)가 분리되어 조합이
곱셈으로 는다. 캐릭터 5명 × 동작 5개를 파츠 5벌과 각도표 5벌로 만든다.
6프레임 합성이 12초다(확산은 34분이었다).

**등신은 생성이 아니라 합성에서 정한다.** 머리를 1/N 로 줄이고 남은 길이를 상체와
다리가 나눠 갖되, 등신이 커질수록 다리 몫을 늘린다 — 같은 비율로 늘리면 치마만
길어진다. 가로는 그대로 두므로 다리가 굵어지지 않고 길어진다. 3·4·5·7등신에서
목표 대비 오차 0.14 이내였고, 네 변형 모두 액세서리가 같은 픽셀이다.

한계는 정직하게 — 2D 평면 회전이라 원근이 없다. 팔은 아직 상체에 붙어 있다.
정면 기준 포즈라 팔이 몸통과 이어져 잘라낼 수 없고, 옆모습은 두 다리가 겹쳐
근/원 다리를 가를 수 없다. 팔을 쓰려면 팔을 벌린 3/4 기준 포즈가 필요하다.

## 수명 — 레시피는 영구, 픽셀은 소모품

```
생성 → ~/ComfyUI/output/     원천. 읽기만 한다
     → catalog/              썸네일·레시피 영구 · 원본 30일
     → flag                  만료 면제, 공개 후보
     → public/ → Vercel      골라 공개
```

썸네일은 원본보다 130배 작다(1000장에 약 4MB). 썸네일과 레시피는 영원히 두고 원본
픽셀만 만료시킨다. **만료는 손실이 아니다** — 레시피가 남아 `./forge replay`로 다시
만든다. 유예 기간은 `catalog/config.json`의 `retain_days`. 알파는 끝까지 지킨다.

`~/ComfyUI`는 건드리지 않는다. 만료는 이 저장소 안의 복사본만 지운다.

## 필터는 태그가 아니라 패싯이다

itch.io의 사이드바 구조를 따르되 축이 다르다. itch는 사람이 붙인 태그를 쓰고, 여기는
**기계가 뽑은 값**을 쓴다 — 모델·LoRA·크기·생성일·상태(배경 투명·파츠 리깅 포함).
손으로 태깅할 일이 없어 목록이 낡지 않는다.

fantasy·sci-fi 같은 의미 태그는 넣지 않았다. 자동 추출이 안 되고, 손으로 붙이는 순간
옛 실패를 되풀이한다.

## 디자인

`design/`이 원본이고 `web/`이 구현본이다. logo_d와 같은 구조다.

시각 언어는 `studio_d` Logo Guide v1.0에서 나온다. 금지 조항이 UI를 직접 제약한다 —
그라디언트·외곽선·드롭섀도가 금지이므로 **허용된 깊이 표현은 오른쪽·아래 1u 하드
압출(blur 0) 하나뿐이다.** 카드 호버가 그것이고, 알파 체커도 평면 두 색이다.

`--accent #5EC8C4`는 로고에서 언더스코어 한 글자에만 쓰는 색이다. 여기서도 **공개
플래그 하나**에만 쓴다. 링크·버튼·활성 표시에는 쓰지 않는다.

## 여기서 결정하지 않는다

마스코트가 누구인지, 게임 간 연결이 어떤지는 `studio_d/design-system/WORLD.md`가 쥔다.
흐름: 여기서 후보를 뽑는다 → studio_d가 고르고 확정한다 → 각 게임이 구현한다.

**아주 작은 스프라이트의 최종 픽셀은 찍지 않는다.** 얼굴이 10×10쯤 되면 확산 모델
출력을 그 격자로 줄이는 순간 형태가 뭉개진다. 격자 다운스케일과 팔레트 스냅은
팔레트를 아는 소비자 쪽에 산다. 경계는 크기에 있지 대상에 있지 않다.

## 구조

```
forge          스토어 — 유입·수명·공개
rig            파츠 리깅 — 기준 포즈 한 장으로 동작을 만든다
casts/         캐릭터별 기준 포즈와 파츠 경계
motions/       동작별 관절 각도표
design/        Claude Design 원본 (.dc.html) — 배포 제외
web/           구현본 (index.html · store.css · store.js)
catalog/       index.json · recipes/ · thumbs/ · originals/(추적 안 함)
public/        공개본 — Vercel 루트
```

배포는 https://artforge-store.vercel.app . `main` 에 푸시하면 Vercel이 자동으로 올린다.

```sh
./forge publish --all     # 공개본 갱신 (플래그된 것만 올리려면 --all 을 뺀다)
git add -A && git commit && git push
```

요금제상 프로덕션 주소에 자물쇠를 달 수 없어 `noindex` 와 `robots.txt` 만 넣었다.
접근 제어가 아니다.
