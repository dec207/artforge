# artforge

studio_d의 **모든 디자인과 에셋을 만드는 곳**. 대장간이다.

로고와 사이트 비주얼, 게임 아트, 마스코트가 전부 여기서 나온다.
게임 아트는 그중 하나이지 이 저장소의 정의가 아니다.

프롬프트, 워크플로, 시도한 이미지 수백 장이 여기 산다. 대부분 버려진다.
그것이 이 저장소의 정상 상태다.

## 경계

**여기서 결정하지 않는다.** 마스코트가 누구인지, 게임 간 연결이 어떤지는
`studio_d/design-system/WORLD.md`가 쥔다. 캐논을 대장간에 두면 스튜디오
정체성이 실험 폴더 안에서 매번 다시 태어난다.

흐름: 여기서 후보를 뽑는다 → studio_d가 고르고 확정한다 → 소비자가 구현한다.

**아주 작은 스프라이트의 최종 픽셀은 찍지 않는다.** 얼굴이 10×10 픽셀쯤 되면
확산 모델 출력을 그 격자로 줄이는 순간 형태가 뭉개진다. 그 크기에서는 콘셉트와
조합 후보까지가 artforge의 몫이고, 최종 픽셀은 손이 맡는다.

경계는 크기에 있지 대상에 있지 않다. 웹 해상도에는 이 문제가 없다 —
로고도 사이트 비주얼도 여기서 최종본까지 나온다.

artforge는 **무엇을 그릴지**를 맡는다. 작은 격자에서만 **어느 픽셀을 찍을지**를 넘긴다.

## 어디서 이기는가

크기가 클수록 이긴다. 확산 모델의 약점은 작은 격자로 줄일 때만 나온다.

| 대상 | 크기 | 역할 |
|---|---|---|
| 로고 · 워드마크 | 웹 해상도 | 최종 에셋 후보 |
| 사이트 히어로 · 섹션 비주얼 | 웹 해상도 | 최종 에셋 |
| 마스코트 | 웹 해상도 → 게임 규격 | 후보 — 확정은 `WORLD.md` |
| 타이틀·배경·표지 | 240폭 | 최종 에셋 후보 |
| 게임 일러스트 | 40×40 | 최종 에셋 후보 |
| 액터 스프라이트 | 16×24 | 콘셉트만 — 조합 후보 |

## 납품 방식

PNG 파일로 나간다. 빌드로 묶이지 않는다.

웹으로 가는 것은 PNG 그대로다. 픽셀 게임으로 갈 때만 격자 다운스케일과
팔레트 스냅이 붙고, 그 변환기는 **소비자 쪽에 산다** — 팔레트와 아트 형식을
아는 곳이 거기이기 때문이다. artforge는 팔레트를 몰라도 된다.

## 저장소 지도

`studio_d`와 형제인 독립 저장소다. 자세한 것은 `studio_d/README.md`.

devstory_d는 2026-08-19에 스튜디오 밖으로 나갔다. `PLAN.md`의 1~3단계가 그 게임
전용이라 보류됐을 뿐, 대장간의 일감은 홈페이지로 이어진다 — `PLAN.md` 상단.
